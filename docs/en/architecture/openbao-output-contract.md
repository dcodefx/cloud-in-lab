# OpenBao Output Contract

This document defines the output contract between the OpenBao server, openbao-ops, and k8s_apps plays. Its purpose is to remove the dependency on the `openbao.ip` variable and have IP/port information derived from inventory and written to output files.

## File Locations

* `outputs/openbao/openbao-credentials.yml` - root token and unseal keys
* `outputs/openbao/openbao-unseal-keys.txt` - human-readable summary
* `scripts/openbao-unseal/credentials.txt` - HOST/PORT for the unseal script
* `outputs/openbao/openbao-config.json` - server connection info
* `outputs/openbao/openbao-mount.json` - mount names and address
* `outputs/openbao/pki-manager.json` - k8s_apps dedicated-PKI manager (P2) AppRole credentials
* `outputs/openbao/ops-admin.json` - operational jobs (P4) AppRole credentials
* `outputs/openbao/monitor.json` - monitoring/telemetry reader AppRole credentials
* `outputs/openbao/bao-raft-agent.json` - raft snapshot agent (B10, read-only) AppRole credentials
* `outputs/openbao/bao-raft-restore.json` - raft restore (B10+B11, write) AppRole credentials

The last five files are generated in a **data-driven** way from the
`openbao_platform_credentials` list in `roles/openbao/security/defaults/main.yml`;
as the list grows, a new role's `.json` file is generated automatically.

## openbao-config.json

Generated by `roles/openbao/server/tasks/init.yml` when server init succeeds.

```json
{
  "host": "164.102.98.186",
  "port": 8200,
  "address": "https://164.102.98.186:8200",
  "generated_at": "2026-09-06T12:00:00Z",
  "openbao_version": "2.6.2"
}
```

`host` is derived from `hostvars[groups.openbao[0]].ansible_host`. `port` comes from defaults.

## openbao-mount.json

Generated by `roles/openbao/server/tasks/bootstrap.yml` during OpenBao server bootstrap (runs with the root token, together with rbac-platform.yml).

```json
{
  "approle_mount": "approle",
  "transit_mount": "transit",
  "pki_mount": "pki",
  "pki_int_mount": "pki-int",
  "kv_mount": "secret",
  "address": "https://164.102.98.186:8200",
  "generated_at": "2026-09-06T12:00:00Z",
  "openbao_version": "2.6.2"
}
```

When `use_default_mounts` is true, mount names are taken from the `outputs/openbao/openbao-mount.json` produced by the OpenBao server bootstrap. When false, the manual values in `group_vars/all/all.yml` are used.

## AppRole credentials (pki-manager, ops-admin, monitor, bao-raft-agent, bao-raft-restore)

Generated from inside bootstrap with the root token by `roles/openbao/security/tasks/rbac-platform.yml`
(for each role in the `openbao_platform_credentials` list):

```json
{
  "role_id": "…",
  "secret_id": "…"
}
```

Files are written with `0600` permissions and `no_log: true`. Consumers:

- `ops-admin.json` — operational roles (openbao-ops) log in from this file on every run; the root token is never used inside this role (openbao-rbac.md §6.2).
- `pki-manager.json` — reader for dedicated-PKI role management (openbao-rbac.md §3, P2).
- `monitor.json` — Prometheus/telemetry read profile.
- `bao-raft-agent.json` — `roles/openbao/server/tasks/backup.yml` distributes
  this pair as `/etc/bao/snap-bao-raft-agent-roleid` and `snap-bao-raft-agent-secretid`
  (`0640 bao:bao`); `bao agent` reads them via `auto_auth`.
  Policy is **read-only** (B10) — a service exposed 24/7 cannot write back to the raft store.
- `bao-raft-restore.json` — the same task distributes `snap-bao-raft-restore-roleid` /
  `snap-bao-raft-restore-secretid`; `maintenance/restore/restore-openbao.sh`
  performs a **one-shot** AppRole login with them (token is never written to disk).
  Policy is B10+B11 — it carries restore write permission.

## Consumption

* `roles/k8s-apps/app-deploy/tasks/dedicated-pki-domains.yml` first checks whether a dedicated request exists.
* If so, `outputs/openbao/openbao-mount.json` and `outputs/openbao/pki-manager.json` are read.
* `roles/openbao/server/tasks/backup.yml` reads the raft profile's `.json` pair and
  distributes it under `/etc/bao/`; if the file is missing, the play stops immediately
  (**fail-fast**, when `openbao_backup_enabled: true`).
* If the file is missing, the play fails, requesting that `openbao.yml` be run (bootstrap → rbac-platform).


## Versioning

`generated_at` is kept in RFC3339 UTC format. On the K8s Apps side, a 30-day file-age check is recommended.
